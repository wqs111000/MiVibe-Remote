# Windows 遥控器适配与验证记录

## 已验证的方案

在 Windows 上使用支持 ATVV 语音的新小米遥控器，通过蓝牙连接 MiVibe Remote：

```text
遥控器内置麦克风 → 蓝牙 ATVV → MiVibe Remote 解码 → CABLE Input
                                                       ↓
Codex 听写 ← CABLE Output ← VB-CABLE
遥控器语音键 → MiVibe Remote 模拟按住听写快捷键 → Codex
```

Codex 负责将声音转成文字。真实测试中，按住新遥控器语音键说话，松开后 Codex 输入框
出现了正确文字；测试没有发送消息。此前也单独播放过遥控器采集的录音，由使用者确认声音正常。

实体按键测试：在 Codex 草稿输入 `ABC`，按一次遥控器左方向键，再按一次返回键，结果为
`AC`。这验证了左方向键和退格；其他按键的实际效果仍需逐一测试。

## 设备选择

本次可用的新遥控器蓝牙设备标识为 `VID 2717 / PID 32B8 / REV 00A4`，发现了 ATVV 服务
`ab5e0001-5a21-4f05-bc7d-af01f617b664`。配对成功只是第一步，还需要确认语音链路和实际收音。

此前测试的旧遥控器为 `VID 2717 / PID 32B8 / REV 0004`：普通按键可用，但当时没有找到可用
的语音通道。它以前在电视上能正常语音识别，因此这次失败不能证明其麦克风硬件不可用；也不能
只凭相同的 VID/PID 就认为两种版本的语音协议兼容。

## 配置和复测

1. 在 Windows 蓝牙设置中配对遥控器，启动 MiVibe Remote，并检查应用中的设备和语音链路状态。
2. 从应用的语音驱动助手运行 VB-Audio 官方 VB-CABLE 安装器。按照安装器提示处理管理员授权；
   如果提示重启，保存工作后手动重启。确认 Windows 中有播放端点 `CABLE Input` 和录音端点
   `CABLE Output`。
3. 在 Codex 的语音设置中选择 `CABLE Output`。在 MiVibe Remote 使用 Codex 预设、语音键
   “按住型”，并让它的快捷键与 Codex 的“按住听写”完全一致。
4. 本机的右 Alt 被 Typeless 占用，因此两边改用 `Ctrl + Shift + F9`，保存并应用后完成了验证。
   这只是本次可用的组合；其他电脑应按自己的软件配置选择未冲突的快捷键。
5. 将光标放在 Codex 空白输入框，按住遥控器语音键说话，松开后检查文字，先不要发送。再用
   上面的 `ABC` 测试确认方向和返回键。

## 排查顺序

- **已配对但无语音**：先确认设备版本和 ATVV 语音链路，再用实际收音和试听验证；不要把蓝牙
  连接或应用进程运行当作麦克风已经可用的证明。
- **能收音但 Codex 没文字**：检查 VB-CABLE 两个端点、Codex 选择的 `CABLE Output`、两边
  快捷键和按住型设置。先用电脑键盘测试 Codex 快捷键，再测试遥控器，排除其他软件占键。
- **首次设置后无反应**：本次曾出现过快捷键没有触发，后来重新确认设置并实际触发后成功；
  没有确定唯一根因。应以键盘和遥控器的实际复测为准，避免把某一次现象当成通用结论。
- **驱动助手失败或端点缺失**：查看应用显示的错误，检查安装器是否完成、是否需要重启；
  不要为了排查随意重启所有 USB 设备。

诊断抓包、录音和日志可能包含语音或设备标识，分享或提交前应先检查并移除敏感数据。
